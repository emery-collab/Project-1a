============================================================
1. OVERVIEW
============================================================
A Galaga-style shooter built on our own game engine. The engine (engine/)
handles the game loop, drawing with per-object offsets/rotations, collision
detection between lines, circles and rectangles, keyboard-to-notification
mapping, and a notification manager. The game (galaga/) is driven by a single
Galaga game object that main.cpp adds to the engine.

Controls:
  5            insert a coin (5 needed)
  1            start the game
  A / Left     move left
  D / Right    move right
  Space        fire

============================================================
2. GALAGA STATE FLOW (galaga/Galaga.h/.cpp)
============================================================
Galaga runs a finite state machine (enum class States). Galaga::Update calls
the function for the current state every frame. ChangeState() switches state
and records the frame it started on (mStateStartFrame), which is used as a
timer with context->currentFrame.

  WaitingForGameToBegin
      Shows the coin count. Waits for 5 coins and the start key.
          |
          v
  StartUp
      Shows the stage, waits 60 frames, spawns the player, resets the wave
      counter.
          |
          v
  Waves
      Every 60 frames spawns one wave of 8 enemies (one row), 5 waves in
      total. Each wave mixes types by column (2 Enemy3, 4 Enemy2, 2 Enemy1).
      Each enemy gets its formation spot and an entry Bezier path.
          |
          v
  GamePlay
      Every 120 frames selects enemies to attack (see section 3). If the
      player dies -> Respawn (or GameOver at 0 lives). If all enemies are
      destroyed -> next level, back to StartUp.
          |                         ^
          v                         |
  Respawn                           |
      Shows the remaining lives. Waits until no enemy is attacking, then
      spawns a new player and returns to GamePlay.

  GameOver
      Shows "GAME OVER" for 90 frames, kills all objects, resets score,
      lives, level and coins, and returns to WaitingForGameToBegin.

3. DESIGN DECISIONS
============================================================
Enemies (galaga/Enemy.h/.cpp, Enemy1/2/3)
  - Enemy is an abstract base class with a pure virtual Attack(). The common
    logic (following Bezier curves, hovering, firing, collisions) lives in
    Enemy; Enemy1/2/3 differ in health, drawing, and their attack curve.
  - Each enemy has its own state (enum class EnemyStates):
      kEntering  - follows the entry path given by Galaga
      kWaiting   - in formation, hovers side to side
      kAttacking - follows its attack path, firing, and ends back home
  - Attack(context, target) returns false unless the enemy is in formation.
    Otherwise it builds a new 7-point Bezier path (home -> near the player ->
    home), resets t, switches to kAttacking and returns true.
  - Constant speed: t is advanced by (pixels per frame / |slope|), using the
    Bezier derivative, so enemies move at the same speed along any curve.
  - Hovering uses sin(currentFrame), so all enemies hover in sync.
  - Health: Enemy1 = 1, Enemy2 = 2, Enemy3 = 3. Enemies with more than one
    health change color as they are hit.
  - Enemies fire at most once every 60 frames while attacking.

Attack selection (Galaga::GamePlay)
  - Deterministic, no randomness. Every 120 frames Galaga iterates over the
    engine's objects (EngineView iterator + dynamic_pointer_cast) and sends at
    most one enemy of each type to attack, skipping the first `offset` of
    each type. offset increases every round and wraps to 0 when no enemy
    could attack, so different enemies take turns.

Scoring (notifications)
  - When an enemy dies it sends one of six notifications, e.g.
    "Enemy1DestroyedInFormation" / "Enemy1DestroyedOutFormation".
    Galaga registers for all six and awards points:
        Enemy1: 100 in formation, 200 out of formation
        Enemy2: 200 / 400
        Enemy3: 300 / 600

Respawn
  - Galaga waits until no enemy is in kAttacking (checked through the new
    public Enemy::GetState()) before respawning the player.

IMPLEMENTATION NOTES
============================================================

MathUtils
---------
  - Implemented a line-line Crosses() function that calculates the variables
    needed for the intersection equations derived in class, checks for parallel
    lines, and then uses u and t to determine whether the lines intersect. If
    they do, it returns true and sets the crossing point.
  - AI review suggested checking whether the denominator is within epsilon of
    zero rather than checking whether it equals zero exactly, since floating-
    point arithmetic can produce values extremely close to zero.
  - Implemented ClosestPoint() and other outstanding tasks, including ostream
    operators. ClosestPoint() finds the actual closest point on a line rather
    than checking only its endpoints.

CollisionObject.h
-----------------
  - Added the code described in the assignment and updated Player, Enemy, and
    Bullet to implement GetShapes(), GetRotation(), and GetLocation() from the
    new virtual functions in CollisionObject.h.
  - In Player.cpp, converted a world-coordinate rectangle to local coordinates.
    AI was used to help identify and correct the coordinate-space issue.

DrawContext.cpp
---------------
  - Implemented FrameRect() by finding the four corners of a rectangle and
    drawing lines between them.
  - Added Transform(Point2D), Transform(Rect), and ReverseTransform() to handle
    rotations, then updated the drawing functions to respect the current
    transformations.
  - Added SetContextOffset() and SetContextRotation() so GameEngine can access
    the private transformation state through setter functions.
  - Used AI assistance to refactor DrawRect() rotation handling. Transforming
    only the object's local position or center was insufficient, so all four
    corners are transformed before drawing the resulting polygon.
  - Each drawing function applies its transformations before drawing, except
    FrameRect(), which uses DrawLine()'s transformation logic.

GameEngine.cpp/h
----------------
  - Updated the engine to support new events.
  - Refactored collision detection to skip object pairs whose bounding boxes do
    not overlap before checking their locations, rotations, and shapes.
  - Used AI assistance to develop and review the collision-detection code, then
    refactored it into lambda functions to reduce duplicated calculations and
    avoid checking equivalent pairs such as line-circle and circle-line.
  - The collision-detection flow in GameEngine::Run() is:
      1. Declare helper lambdas.
      2. Perform reusable calculations, such as transforming points and testing
         intersections.
      3. Compare shapes to determine whether they overlap.
      4. Notify the objects of collisions and provide a contact point for line
         collisions when available.

Bullet.h/cpp
------------
  - Added member variables to track whether a bullet has exploded, the explosion
    location, and how many frames the explosion has remained visible.
  - Updated the collision callbacks to record the collision point and retain
    the point with the largest Y coordinate when multiple points are reported.
  - Updated RenderForeground() to draw a small circle instead of the moving
    line during the explosion.
  - Updated Update() to remove the bullet after the explosion has been visible
    for a few frames.
  - Updated GetShapes() to return no collision shapes after the bullet explodes,
    preventing the lingering explosion from repeatedly damaging an enemy.

Extras
------
  - Refactored several functions, including RenderForeground(), across the
    Galaga files.

Enemy1/2/3.cpp
--------------
  - Added custom Bezier paths for the three enemy types, using vectors of
    Point2D values. The paths begin and end at the enemies' formation spots
    and use the player's coordinates to varying degrees in their calculations.
